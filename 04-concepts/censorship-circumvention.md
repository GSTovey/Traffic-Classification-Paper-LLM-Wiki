# Censorship Circumvention（审查规避）

## 1. 定义

Censorship Circumvention（审查规避）是指绕过国家级互联网审查机制（如中国的 Great Firewall、伊朗的审查系统等）实现自由访问被封锁内容的技术和方法。该领域涵盖三个相互关联的研究方向：

- **审查测量（Censorship Measurement）**：系统性地检测和量化全球互联网审查的范围、方法和影响
- **审查规避工具设计（Circumvention Tool Design）**：设计和实现能抵抗审查检测和封锁的通信协议和工具
- **审查检测与对抗（Censorship Detection & Evasion）**：审查者如何检测规避工具，以及规避者如何抵抗检测

审查规避的核心矛盾在于：审查者控制网络基础设施，拥有比规避者更多的权力和资源（如主动探测、流量分析、IP 封锁等），而规避者需要在不被发现的前提下实现自由通信。

## 2. 核心问题

| 编号 | 问题 | 说明 |
|---|---|---|
| P1 | 可观测性与不可观测性 | 审查规避工具必须在审查者的网络中"不可观测"——不仅内容加密，流量模式也不能暴露工具的存在 |
| P2 | 附带损害（Collateral Damage） | 审查者封锁规避工具时可能误伤正常服务，规避者可利用这一约束设计最大化附带损害的协议 |
| P3 | 主动探测与被动检测 | 审查者既可通过主动探测验证服务身份，也可通过被动流量分析检测规避工具，两种威胁需分别应对 |
| P4 | 协议指纹与行为真实性 | 规避工具的协议特征（如包长度、握手模式）可能形成独特指纹，行为不真实（如浏览模式异常）也会暴露工具身份 |
| P5 | 持续对抗与演化 | 审查机制不断升级（从 IP 封锁到深度包检测到机器学习分类），规避工具也需持续演化 |

## 3. 主要技术路线

### 3.1 审查测量

| 技术路线 | 核心思想 | 优点 | 局限 | 代表论文 |
|---|---|---|---|---|
| 远程测量 (Remote Measurement) | 从全球分布式探测点主动访问被测目标，通过异常检测识别审查行为 | 无需在审查国家部署基础设施；可大规模持续观测 | 探测可能被审查者识别和阻断；无法覆盖所有网络路径 | Censored Planet |
| 被动流量分析 (Passive Traffic Analysis) | 通过分析网络流量的统计特征（包长度、熵、协议指纹）检测规避工具 | 不需主动探测；可在 ISP 级别部署 | 误报率高；需大量标注数据 | How China Detects Shadowsocks |

### 3.2 审查规避工具设计

| 技术路线 | 核心思想 | 优点 | 局限 | 代表论文 |
|---|---|---|---|---|
| 流量混淆 (Traffic Obfuscation) | 通过 padding、随机化、协议伪装等手段改变规避工具的流量特征 | 实现简单；可抵抗基于流量特征的检测 | 无法抵抗基于行为分析的检测；增加带宽开销 | obfs4, Shadowsocks |
| Web 协议隧道 (Web Protocol Tunneling) | 将规避流量伪装为正常的 Web 浏览行为，通过延迟流量替换和用户模拟实现行为真实性 | 流量模式与正常 Web 浏览不可区分；可抵抗行为分析 | 带宽受限于模拟的浏览行为；实现复杂度高 | Huma |
| 未识别协议生成 (Unidentified Protocol Generation) | 自动从真实加密协议的共性特征中采样生成大量结构化加密协议，使封锁必然造成大规模附带损害 | 4.2 x 10^22 种协议变体；性能优于 Obfs4；附带损害保证 | 协议生成器本身需保密；对主动探测仍需额外防御 | UPGen |
| 探测抗性代理 (Probe-resistant Proxy) | 设计能抵抗主动探测的代理服务器，区分合法客户端和审查者探测 | 可抵抗主动探测攻击 | 实现复杂；对新的探测技术需持续更新 | Detecting Probe-resistant Proxies |

### 3.3 审查检测

| 技术路线 | 核心思想 | 优点 | 局限 | 代表论文 |
|---|---|---|---|---|
| 全加密流量检测 | 通过统计规则（popcount 熵、可打印 ASCII 比例等）检测不使用标准协议的全加密流量 | 规则简单高效；可大规模部署 | 规避者可通过协议伪装绕过 | GFW (USENIX 2023) |
| 精确检测 (Precise Detection) | 通过深度学习（CNN、SDAE）和主机级行为分析精确检测审查规避流量 | 在真实网络中验证；支持带拒绝选项的分类 | 需大量标注数据；对新工具泛化能力有限 | Censorship Circumvention Detection (NDSS 2024) |
| 主动探测 (Active Probing) | 通过重放攻击和随机数据探测验证可疑服务的身份 | 可直接验证服务身份；检测精度高 | 可被探测抗性代理防御；需网络控制能力 | How China Detects Shadowsocks |

## 4. 相关方法

- Censored Planet - 互联网规模的纵向审查观测平台

## 7. 当前共识

1. **审查与规避是持续的军备竞赛**：审查技术从 IP 封锁演进到 DPI 再到 ML 分类，规避工具也从简单加密演进到流量混淆再到行为模拟。
2. **行为真实性是规避工具设计的前沿**：仅加密内容和混淆流量特征已不足够，Huma 等工作表明需要模拟真实的用户浏览行为才能抵抗行为分析。
3. **附带损害是规避者的战略武器**：UPGen 利用"封锁必然误伤正常服务"的约束，自动生成最大化附带损害的协议变体。
4. **被动检测与主动探测相辅相成**：GFW 同时使用被动流量分析（首包特征）和主动探测（重放验证）来检测规避工具，规避者需同时应对两种威胁。
5. **远程测量是理解全球审查格局的关键**：Censored Planet 等平台通过大规模远程测量持续监测全球审查动态。

## 8. 争议与矛盾

1. **隐私与安全的张力**：审查规避技术既服务于言论自由，也可能被用于非法活动。技术本身是中性的，但应用场景涉及伦理争议。
2. **研究公开与安全的平衡**：公开审查机制的逆向分析可能帮助规避者，也可能帮助其他审查国家复制审查技术。
3. **可用性与安全性的权衡**：更安全的规避工具（如行为模拟）通常带宽更低、延迟更高，影响用户体验。

## 9. 对我研究的价值

1. **审查检测技术可借鉴**：GFW 的被动流量分析规则（首包长度、熵检测）和主动探测技术与隧道检测研究直接相关。
2. **行为真实性是新方向**：Huma 的延迟流量替换和用户模拟思想可推广到需要抵抗行为分析的其他场景。
3. **协议生成是通用方法论**：UPGen 的协议参数采样思想可应用于其他需要生成多样化变体的安全场景。
4. **大规模测量方法论**：Censored Planet 的远程测量框架对其他网络测量研究有参考价值。

## 10. 后续问题

- 机器学习驱动的审查检测（如基于深度学习的流量分类）将如何改变审查规避的技术格局？
- QUIC/HTTP3 等新协议的普及是否会影响基于协议指纹的审查检测方法？
- 去中心化审查规避（如 P2P 隧道、域名前置等）能否从根本上解决中心化规避工具的封锁问题？
- 如何评估规避工具在不同审查国家（如中国、伊朗、俄罗斯）的通用性？
- 规避工具的"不可观测性"是否有信息论下界？
