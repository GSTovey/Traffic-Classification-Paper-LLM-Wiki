# Encrypted Network Trafic Classification Using Generative and Contrastive Self-Supervised Learning

Md. Shamim Towhid and Nashid Shahriar , Member, IEEE

Abstract—Network trafic classification is crucial for various applications, encompassing network provisioning, malware detection, and resource management. In contemporary networks, the prevalence of encrypted protocols presents a challenge to existing classification techniques. Deep learning has exhibited promising results in encrypted trafic classification; however, its reliance on extensive labeled data impedes its eficacy in real-world scenarios where labeled data is scarce. This paper explores self-supervised learning, specifically generative and contrastive learning, as a solution to this challenge. While self-supervised learning is wellestablished in computer vision and natural language processing, its application to sequential data like network trafic remains unexplored. The paper utilizes two self-supervised approaches, generative and contrastive, tailored to achieve high accuracy in classifying encrypted network trafic with minimal labeled data. Evaluation across four publicly available datasets shows that the proposed self-supervised approaches outperform corresponding supervised baselines, an existing self-supervised method, and two state-of-the-art few-shot learning approaches by approximately 3%, 11%, and 17%, respectively in terms of accuracy. In addition, the proposed approaches exhibit transferability, showcasing the ability to apply learned knowledge to diferent datasets not seen during training. This paper advances the understanding and application of self-supervised learning in the domain of network trafic classification, ofering viable solutions for scenarios with limited labeled data.

Index Terms—Self-supervised learning, network trafic classification, encrypted trafic.

## I. INTRODUCTION

M <sup>ODERN</sup> <sup>networks</sup> <sup>are</sup> <sup>becoming</sup> <sup>increasingly</sup> <sup>complex</sup>to support the heterogeneous needs of a variety of to support the heterogeneous needs of a variety of Internet applications. Automation is necessary to manage these complex networks [1]. Network trafic classification is usually the first step in any automated network management system. It allows network operators to analyze trafic and identify diferent types of applications in a network which can be used to manage the overall performance of the network. Communication in modern networks is done by exchanging packets which are created by segmenting data according to some protocol. As a result, there is a flow of packets from one network device to another. Classification of this flow of network packets refers to the identification of applications of the trafic by observing the characteristics of the trafic flow. Encrypted network trafic classification involves identifying the applications of the trafic being transmitted over encrypted channels [2]. This encryption poses a challenge due to the inability to inspect the payload content of packets.

Encrypted network trafic classification has numerous practical applications in today’s digital landscape. Some notable applications are Quality of Service (QoS) provisioning, malware detection, and anomaly detection [3]. Network administrators can analyze encrypted network trafic and identify patterns associated with diferent types of trafic, deducing application classes or anomalous behavior. Accurate classification of network trafic can enhance the security of computer networks and alert administrators about potential threats. It can help network administrators manage and optimize network resources by diferentiating between diferent types of trafic, such as video streaming, file downloads, or real-time communication.

Due to wide variety of applications and the use of diferent protocols, network trafic classification becomes a challenging task. Moreover, the development of encrypted protocols (e.g., HTTP/2 [5] and QUIC [6]) and wide acceptance of these protocols in network communication exacerbate the complexity of network trafic classification. In the past, machine learning techniques showed promising performance in trafic classification. In [7], machine learning (e.g., Na¨ıve Bayes, Decision Trees) models are trained on a set of flow statistics selected by domain experts. Some more machine learning approaches (e.g., C4.5, SVM, K-means, KNN) are explored in [8]. However, these approaches cannot be used to classify encrypted network trafic since these techniques rely on handpicked features, which cannot be extracted from encrypted trafic. Researchers employ supervised deep learning, a subset of machine learning, to address encrypted network trafic classification because of its automatic feature selection capability [9]. However, supervised learning methods necessitate substantial labeled data, which is time-consuming and prone to errors in creation.

Another approach from machine learning domain called self-supervised [10] is gaining traction due to its reliance on a small amount of labeled data to achieve good accuracy.

Unlike few-shot learning approaches [13], [14], [15], [16] where the aim is to train models to generalize from a small number of labeled data, self-supervised approaches try to learn a representation of unlabeled data that is used for the downstream task later on. Usually, a self-supervised learning algorithm has two stages [10], [11], [12], [18]. The first stage is called pre-training where a model learns to represent data diferently based on some property of the data rather than the actual label. The next stage is called fine-tuning where the weights of the model are fine-tuned based on a small amount of labeled data of the actual task. The intuition is that if the model can learn a good representation of the data in the pretraining stage, a small amount of labeled data are suficient in the fine-tuning stage to achieve high accuracy. The overall performance of the model highly depends on the given task and the amount of unlabeled data in the pre-training stage. Self-supervised learning algorithm is suitable for encrypted network trafic classification since it is easy to capture lots of trafic data from a network but the tedious part is to create the label for every captured flow of packets.

Self-supervised learning approach can be categorized into two broad classes based on the approach taken in the pre-training stage: generative and contrastive. In generative learning, models reconstruct the original input from a corrupted version, while in contrastive learning, they learn by comparing augmented versions of the same input. In this paper, we study the applicability of both classes of self-supervised learning for the task of encrypted network trafic classification. We first propose a masking technique for introducing noise in the pre-training stage of generative learning to obtain corrupted data. Afterward, an incremental sampling technique is proposed to prepare augmented data for contrastive learning. The preparation of augmented versions of encrypted network trafic is challenging due to the numerical format of network flow. Therefore, we divide a network flow into multiple sub-flows using incremental sampling and use one randomly picked sub-flow as an augmented version of another sub-flow. In this way, we ensure that the class label of the network flow does not change due to augmentation. Finally, we analyze the performances of the proposed self-supervised learning approaches on publicly available datasets.

This paper extends our preliminary work presented in [23] on several aspects. First, we present a novel generative self-supervised learning (GSSL) approach for encrypted network trafic classification. We also discuss the advantages and disadvantages of both GSSL and the previously proposed contrastive self-supervised learning (CSSL) approaches. Furthermore, we present additional evaluation results of the proposed approaches on a publicly available large-scale dataset (e.g., AppClassNet [27]). We include additional evaluation metrics (precision, recall, F1 score) in addition to accuracy, to provide a more comprehensive assessment of the proposed methods. Additionally, we compare our proposed self-supervised approaches with two state-of-the-art few-shot learning approaches in Section IV. ## II. RELATED WORK

As network trafic classification is a well-known problem, there is a plethora of research work on this topic. Many researchers have tried to apply traditional machine learning methods to distinguish between protocols (e.g., DNS, SMTP, and HTTP) in a network trace [7], [8]. The accuracy of these traditional approaches has declined because of their simplicity and inability to capture complex trafic patterns [19]. We focus on the application of deep learning for encrypted network trafic classification works from the literature. We broadly categorize the existing works into four categories as described below.

## A. Supervised Deep Learning Approaches

Encrypted trafic classification is more challenging because it often operates on non-standard port numbers. Supervised deep learning approaches are well-suited for such tasks because they can process large, fine-grained feature representations, such as raw trafic bytes. These models can learn complex patterns directly from raw trafic data. In the supervised deep learning domain, Multilayer Perceptron (MLP), Convolutional Neural Network (CNN), and Long Short-Term Memory (LSTM) models have been widely explored in recent literature [20], [21], [24], [25], [26]. Akbari et al. [2] propose a stacked LSTM and CNN-based tripartite neural network architecture to classify encrypted network trafic. Their approach uses three types of features: flow statistics, raw bytes, and time-series features. For the time-series, they consider the packet inter-arrival time within a flow, the packet length, and the packet direction. As a supervised method, the proposed approach relies on a substantial amount of labeled data to achieve high accuracy.

Other studies [28] explore ensemble learning for network trafic classification. In [28], the authors propose an ensemble of CNN models. However, the underlying principles of ensemble learning difer from those of self-supervised learning. Ensemble learning is a supervised approach that typically requires a large labeled dataset for training. This is evident in [28], where the proposed ensemble model is trained using a significantly larger labeled dataset compared to our approach. Transformers [29] have recently gained popularity for modeling sequential data due to their success in Natural Language Processing (NLP). A transformer-based classification framework for time-series data is proposed in [32]. Lin et al. [33] introduce a multi-modal transformer-based model that utilizes raw bytes and packet length features to classify encrypted network trafic. Nevertheless, these supervised deep learning approaches generally rely on large labeled datasets for efective training.

## B. Semi-Supervised Deep Learning Approaches

We distinguish between semi-supervised and self-supervised approaches because the goal during the pre-training stage is diferent. In the semi-supervised approach, the goal is to prepare pseudo labels during pre-training, whereas in selfsupervised approaches, the goal is to learn the representation of input data in high dimensional feature space that satisfies some constraints. Shahraki et al. [4] proposes an active learning-based semi-supervised approach to reduce the need for a large number of labeled data. In active learning, the main idea is to select a few examples from the input data to be labeled. The model benefits the most from these selected and labeled training examples. In [34], Iliyasu and Deng propose another semi-supervised approach for encrypted trafic classification. A deep convolutional generative adversarial network is used in their approach. However, the accuracy of their approach is lower than the other semi-supervised approach such as those mentioned in [3]. An autoencoder-based neural network is proposed in [22] to cluster the network flows based on their similarity in high-dimensional feature space. Then, a semi-automatic labeling method is used to set labels to the cluster. Since this is an unsupervised approach it does not require any labels during training but researchers have found that instead of using completely unsupervised training, a few labeled data samples help deep learning models to achieve better accuracy [10], [11], [12], [35].

## C. Few-Shot Learning Approaches

Few-shot learning is another branch of ML that deals with the problem of a limited number of labeled data during training of a deep learning model. Over the years, researchers have proposed diferent ways [13], [14], [15], [16] to apply fewshot learning in various domains. Snell et al. [13] proposed a metric-based learning approach called Prototypical Networks (ProtoNet) that computes a prototype (mean vector) for each class and classifies new samples based on the closest prototype in feature space. An optimization-based few-shot learning approach is proposed by Finn et al. [14] where the model’s parameters are optimized in a way that it is easily adaptable to new classes with a small number of labeled data. Another way of few-shot learning is to augment the model with external memories, where information related to prior tasks is stored and reused during the training. Vinyals et al. [15] proposed to combine metric learning with external memories (MatchingNet).

In [16], Zhao et al. propose a few-shot learning approach for the Internet of Things (IoT) trafic classification where features are extracted from network flow by a model and multiple comparison models are trained with the extracted features during the training phase. Later, an ensemble of these comparison models is used to classify a network flow. Based on the availability of the source code, we compare our proposed self-supervised learning approaches with ProtoNet [13] and MatchingNet [15] in Section IV. Both of our proposed approaches outperform these two compared approaches in terms of accuracy. Few-shot learning is typically applied when we want to add new classes with limited labeled data to an already trained model. However, if the goal is to train a model from the beginning using a small amount of labeled data, fewshot learning algorithms may not be the most suitable choice. In contrast, self-supervised learning leverages unsupervised pre-training to learn data representations in the feature space. As a result, a small amount of labeled data is suficient to achieve higher accuracy.

## D. Self-Supervised Deep Learning Approaches

Among existing self-supervised learning approaches proposed for encrypted network trafic classification, the approach in [3] is closest to our approaches. In [3], the authors propose to train a CNN model in the pre-training stage to predict the statistics of the whole flow of packets using a sampled subflow. They use three diferent sampling techniques to create sub-flow in their paper which are fixed sampling, random sampling, and incremental sampling. We adopt one of their sampling techniques in this paper and use that as a form of augmentation for our proposed CSSL approach. The authors in [3] utilize only time series-based features i.e., inter-arrival time, packet size, and direction, whereas in our approaches we use at most two features. Although the authors categorize the proposed approach as semi-supervised, according to our definition, this is a self-supervised approach that requires fewer labels compared to supervised methods and does not create any pseudo labels during pre-training. According to the approach taken in the pre-training stage, we cannot categorize the proposed method in [3] into contrastive or generative approach. Therefore, we refer to the approach in [3] as the selfsupervised baseline in the rest of this paper and compare our proposed approaches with this baseline in our evaluation using the same dataset. With the same number of labeled data, our proposed methods outperform the self-supervised approach in [3] in terms of accuracy. Furthermore, according to [3], in a transfer learning setup where the model is pre-trained using a diferent dataset, the accuracy drops by almost 15%. In a similar setup, the accuracy of our proposed contrastive approach decreases only 2%.

The authors in [35] adopt the self-supervised approach proposed in [11] and apply that to time series data classification. Zhao et al. [36] utilize an encoder-based model for extracting robust features using the contrastive learning approach. An augmenter is used to create multiple augmented samples from input data. These augmented versions of input data are used to contrast between them and learn meaningful features during contrastive training. One limitation of this approach is that there is no way to verify whether the augmented version of the data generated by this proposed method are from the same class or not. If the augmented data are similar to another class, then it can hamper the pre-training by learning similar representations for two classes in the dataset. Furthermore, Yue et al. [37] proposed a contrastive cross-entropy loss function that optimizes the feature distribution and prediction of the model for intrusion detection. The contrastive tasks are based on heuristic methods in [37]. Hussey et al. [38] introduced a positive and unlabeled learning approach for mobile application trafic classification. Their method trains a selfsupervised learning model iteratively by designating one class as positive while treating all remaining classes as negative in each iteration. Although efective, this iterative procedure can substantially increase training time when applied to deep neural networks, as observed in our experiments. Moreover, their evaluation was conducted on a dataset in which each class contained at least 1,000 samples, whereas our datasets contain significantly fewer labeled samples per class. In addition there are no evaluations in all the above-mentioned works [35], [36], [37], [38] to analyze the transferability of the proposed approach.

The problem with all these proposed contrastive approaches discussed above is that they require negative samples to be present in the same batch during the contrastive learning stage. In contrastive learning, when we calculate the loss for a data sample, the augmented versions of that sample are referred to as positive samples, and all other data points from the batch are referred to as negative samples. The objective is to learn representations where these positive samples are mapped closer together and negative samples are pushed farther apart. Since we do not use actual labels in the pre-training stage, it is not possible to determine whether the selected negative samples are from diferent classes or diferent data points from the same class. In [11], this problem is addressed by assuming that if we select a large batch size for training, the selected negative sample will be from another class with a high probability. Our proposed contrastive method eliminates this requirement of negative samples by following [12]. The authors in [12] eliminate the requirement of negative samples by training an online network to predict the representation of a target network, which is updated as an exponential moving average of the online network. This self-distillation framework, proposed in the computer vision domain, enables representation learning using only positive pairs derived from diferent augmentations of the same image.

To summarize, our proposed self-supervised learning approaches require much less amount of labeled data compared to existing supervised approaches. In addition, the working principle of our proposed approaches difers from the existing semi-supervised and few-shot learning approaches in terms of learning useful representations of data rather than adding pseudo labels or relying on meta-learning techniques to adapt to new classes, respectively. Compared to the majority of existing self-supervised approaches, our proposed CSSL approach eliminates the requirement for negative samples and utilizes incremental sampling to prepare augmented versions of input data. We also propose a masking technique in combination with transformer model architecture for our GSSL approach that has not been explored in the domain of encrypted network trafic classification.

## III. METHODOLOGY

Both our proposed generative and contrastive approaches follow a typical two-stage self-supervised technique. In the pre-training stage, a neural network is trained to learn the representation of input data. The distinction between our generative and contrastive approaches lies in the task assigned during the pre-training stage. The second stage of training is called the fine-tuning stage which is consistent across both the proposed approaches. This section introduces four public datasets used in our experiments, followed by the proposed approaches and data preparation steps.

## A. Datasets

Before discussing the datasets, we define flow because data is available in the dataset in the form of trafic flows. A flow is a collection of network packets between two hosts having the same source and destination Internet Protocol (IP) addresses, port numbers, and protocol. A packet going from the source to the destination of a flow is called a forward packet (the direction is forward). Otherwise, the packet is called a backward packet (the direction is backward).

QUIC: Rezaei and Liu have released the QUIC dataset used in their research [3]. This dataset consists of 6589 flows, classified into Google Docs, Google Drive, Google Music, Google Search, and YouTube. Since all the flows in the dataset are collected using Google services, the transport layer protocol is QUIC for all of them. Each flow is represented as a text file in this dataset. Each of the text files has four columns describing the timestamp, relative time (from the first packet in the flow), packet length, and packet direction (forward or backward). This dataset is partly generated by human users and partly by automated scripts.

Orange’20: The authors of [2] released the Orange’20 dataset collected from a prominent European ISP’s mobile network for approximately 80 minutes on July 11, 2019. To preserve user privacy, IP addresses are masked, and packet payload content is reduced to TLS headers. This publicly available dataset comprises 119,451 flows categorized into 19 application-level classes. Due to varying flow counts per class, such as Gmail with only 454 flows, ensuring a suficient amount of unlabeled data for self-supervised learning is challenging. To address this, we merge similar classes into a larger and more generic class and create the merged Orange’20 dataset, which includes Social (Facebook, Twitter, Instagram) and Streaming (YouTube, Netflix, Snapchat, Facebook) classes.

ISCX: The authors of [40] have published the ISCXVPN2016 dataset. Both the captured pcap (Packet Capture) files and the generated flow-based features (described in [40]) are available in the dataset. There are a total of seven types of flows in this dataset. The authors capture these seven types of flows once by using VPN and another time without VPN by defining a set of tasks for two pseudo-user profiles. Some of the pcap files are broken in the dataset. The same problem with the ISCXVPN2016 dataset was previously reported [34]. As a result, in our version of the dataset (referred to as ISCX), we have only three classes instead of seven classes and 76 flows in total.

AppClassNet: AppClassNet is a commercial-grade dataset for application identification research, made available by the authors of [27]. This dataset is collected from a real environment and annotated by using commercial and proprietary deep packet inspection systems. In our experiments, we work with the trafic flows from the top 200 applications in this dataset. The AppClassNet dataset is imbalanced. However, the lowest number of flows in a class is 2109. We hypothesize that this number of flows is enough for a deep-learning model to learn the trafic pattern. Therefore, we do not perform any merge operation similar to the ones performed on the Orange’20 dataset. There are 9.7 million trafic flows from the top 200 applications in the dataset. As for the features, the packet size (in bytes) and the direction (forward or backward) of the first 20 packets of a flow are available.

## B. Generative Self-Supervised Learning (GSSL)

In the GSSL approach, the task of the model in the pretraining stage is to generate the original input of the model by taking a corrupted version of it. There are many ways to corrupt the input data. For example, we can simply add noise to the data to corrupt it. By learning to generate original input data from the corrupted version, the model learns the underlying distribution of the data. Since we use the original input as the correct output of the model, we do not need any data labeling in this pre-training stage. The idea of the GSSL is to use a lot of unlabeled data $( G _ { U } )$ in the pre-training stage to learn the underlying distribution of the whole dataset. Then this model can be fine-tuned with only a few labeled data $( G _ { L } )$ for the downstream task, which is classification in our case.

1) Data Preparation: In all four datasets utilized in this paper, two common features are packet direction (forward or backward) and packet size. The GSSL approach yields better results when incorporating packet direction and packet size in a combined format. This combination involves encoding packet direction by utilizing the sign of packet size, where a negative sign indicates backward direction and a positive sign indicates forward direction. An additional important consideration is flow size, defined as the total number of packets within a single flow (the X axis of Figure 1 shows packet indices of a single flow). To ensure consistent input data for model training, trafic flows are standardized to a specified size by either truncating or padding. Flows shorter than the desired size are padded with zeros, while excess size is truncated. This preprocessing step is applied uniformly to all datasets except AppClassNet, where the dataset is already preprocessed with a fixed flow size of 20. For the remaining datasets, a desired flow size of 1024 is targeted. Notably, experimental findings (Table III) indicate a decline in the performance of the generative approach when utilizing a shorter flow size.

2) Pre-Training Stage: In the pre-training stage, we use a transformer-based encoder-decoder architecture [29] to learn the data distribution from an unlabeled dataset $( G _ { U } )$ . Fig. 2 illustrates the pre-training procedure. To introduce noise into the input, we apply random masking, where a subset of the packets is randomly masked out according to a predefined sampling ratio. The packet sequence itself remains in the original order, but some positions are missing due to masking. To enable the model to distinguish between diferent positions and to reason about order and relative distances, we add positional encodings to the input tokens, following the method proposed in [29]. These encodings provide a structured representation of positional information that helps the model infer sequence order even when portions of the input are masked. The positional encoding (PE) values are calculated using the following formulas:

$$

Here, i is the position along the embedding vector dimension and L is the total length of the embedding vector. The value of even positions in the embedding vector is calculated using the sine formula (Eqn. 1), and the value of odd positions is calculated using the cosine formula (Eqn. 2).

After the random sampling of the embedded vector, we use the resulting samples as input to an encoder model. This encoder is a stack of transformer encoder layers. After getting the output from the encoder, which is a compact representation vector of a flow, we insert the masked input in the output vector of the encoder by following [30]. We fill these masked positions with the value zero. Afterwards, the prepared sequence is given to the decoder model. Our decoder model also uses a stack of transformer layers. The task of the decoder model is to predict the original input. We use Mean Squared Error (MSE) as a loss function in this step. Our encoder model comprises 12 transformer layers with 15 heads for multi-head attention, while the decoder consists of 6 transformer layers with 8 heads. Both encoder and decoder models have 1024 neurons in the feedforward neural networks. We also experimented with fewer heads (3 in the encoder and 2 in the decoder) and observed only a marginal drop in performance (from 74.69 to 74.10 on the Orange’20 dataset). Although this diference is not statistically significant, we select the higher number of heads in our experiments, as they provided slightly better performance. Nonetheless, the number of attention heads is a tunable hyperparameter that may depend on the characteristics of the dataset.

We make another modification to the transformer layer by following [31]. In [31], the authors investigate the impact of normalization before and after the attention layer in a transformer architecture. The authors found that doing normalization before the attention (pre-LN) solves the problem of vanishing gradients, but the model sufers from representation collapse. On the other hand, performing normalization after the attention (post-LN) solves the problem of representation collapse but sufers from the vanishing gradient problem. By following the proposed architecture in [31], we add two residual connections in the transformer architecture: one residual connection is from pre-LN, which ensures a lower bound on the gradient to avoid the vanishing gradient issue, and another residual connection from post-LN is added to avoid the collapse issue.

We train the model in the pre-training stage for 500 epochs on the unlabeled dataset. A metric known as validation loss is used to select the best model in the pre-training stage. The validation loss is the loss calculated on a small portion of the hold-out training data. After every epoch, we compare the validation loss and save the best model based on the minimum validation loss. Once the training is finished, we take the encoder part of the model from the pre-training stage and move to the fine-tuning stage.

3) Fine-Tuning Stage: In the fine-tuning stage, we take the encoder part of the model and freeze all the layers of the encoder which is a common practice in existing selfsupervised learning approaches [12]. Therefore, no parameters are updated for encoder layers in the fine-tuning stage. Figure 3 shows the steps of our proposed fine-tuning stage.

After freezing all the layers of the encoder model, we add a version of a ResNet [39] neural network on top of the frozen encoder layers for the classification task. The ResNet model takes the representation of the input data from the frozen encoder layers and learns to classify the data into specific classes. We use a small labeled dataset in the fine-tuning stage. So, the training happens by calculating the cross entropy loss between the predicted output and the actual label.

We train for 300 epochs in the fine-tuning stage. We also use the “ReduceOnPlateau” [48] technique on the learning rate. To compare our GSSL training approach with the corresponding supervised approach, we train the supervised models with the same hyperparameters (epochs, learning rate, and regularization) as those used in the fine-tuning stage of GSSL approach.

## C. Contrastive Self-Supervised Learning (CSSL)

CSSL helps models learn useful representations of data without relying heavily on labeled data. It works by creating diferent augmented versions of the same input and comparing them to versions of other inputs. Using a contrastive loss function, the model is trained to bring representations of the same input closer together while pushing apart those from diferent inputs. In doing so, the model learns features that are both meaningful and resilient to variations in the data.

1) Data Preparation: Our CSSL approach uses two types of features from a flow of network packets. One is inter-arrival time (IAT) between two packets in a flow. The other is the direction of the packet. As mentioned earlier, the direction can be either forward (from source to destination) or backward (from destination to source). Note that these two features do not depend on the protocols used for communication. Since we rely on publicly available datasets discussed in the previous subsection, we are restricted to use the available features (e.g., IAT, direction, and packet size) in those datasets. In our experiments with the contrastive learning approach, the highest accuracy (98.01%) is achieved using IAT and direction as features, whereas IAT, direction, and packet length achieve slightly lower accuracy (96.65%) on the QUIC dataset, justifying our decision of selecting IAT and direction for training our models.

In the contrastive approach, similar to the generative approach, two sets of data are required: an unlabeled dataset $( \mathcal { D } _ { U } )$ for pre-training and a labeled dataset $( \mathcal { D } _ { L } )$ for fine-tuning. Since labels are unavailable at the pre-training stage, two flows from the same class are necessary to learn similar representations. Usually, augmentation is used to create additional instances of flows from the same class. Given the challenge of numerical data augmentation potentially altering labels, in our experiment flows are divided into sub-flows by incremental sampling [3]. Dividing flows into sub-flows ofers two advantages: it enables one sub-flow to serve as an augmented version of another sub-flow from the same class and increases the size of the unlabeled pre-training dataset. The pre-training of the model benefits from this large quantity of unlabeled data, as noted in [11].

Incremental sampling divides a single flow into multiple sub-flows using three parameters: $\alpha , \beta ,$ and $\gamma .$ The process begins by selecting α consecutive packets from a flow, skipping $\beta$ packets, and then updating $\beta$ by multiplying with $\gamma$ in each iteration. This continues until the required subflow length is reached, and the same procedure is repeated to generate additional sub-flows with the given length from the original flow. For example, if we aim to create sub-flows of 10 packets given a flow of $3 0$ packets with parameters $\alpha = 5 , \beta = 2 ,$ , and $\gamma = 1 . 5 ,$ the incremental sampling method produces two sub-flows of 10 packets each. These sub-flows can then serve as augmented versions of one another during the pre-training stage of contrastive learning, as they originate from the same flow. A flow identification number, $F \_ i d ,$ is assigned to each sub-flow to maintain traceability. For further details, readers can refer to our previous work [23].

The unlabeled dataset $\mathcal { D } _ { U }$ consists of sub-flows and the flow identification number corresponding to each of the sub-flows. By following [3], we use $\alpha = 2 2 , \beta = 1 0$ , and $\gamma = 1 . 6$ for all our datasets except AppClassNet because we have access to 20 packets per flow for AppClassNet. Therefore, we divide each flow into two equal-length sub-flows with 10 packets for AppClassNet. For the other datasets (Orange’20, QUIC, and ISCX), we sample 45 packets from the entire flow using the incremental sampling method. That means the length of a sub-flow is 45. Given the parameter values for incremental sampling $( \alpha = 2 2 , \beta = 1 0 ,$ , and $\gamma = 1 . 6 )$ , we first take 22 packets and then skip 10 packets from the flow. Next, we take another 22 packets and skip the following $1 0 \times 1 . 6 =$ 16 packets. The subsequent packet completes the required 45 packets in the sub-flow. Therefore, constructing a single subflow requires 71 packets from the flow. The creation of the next sub-flow starts from the 72nd packet and continues in this manner until the last packet of the flow. However, we also vary the sub-flow length in one of our experiments described in Section IV-C.

The labeled dataset, $\mathcal { D } _ { L }$ is a smaller dataset compared to $\mathcal { D } _ { U }$ . For the Orange’20 [2] and QUIC [3] dataset, we have only 30 flows per class to put in $\mathcal { D } _ { L }$ . Note that these flows are not included in the set that is used to prepare $\mathcal { D } _ { U }$ . These 30 flows per class are randomly selected from the set of all flows. The length of each sub-flow in $\mathcal { D } _ { L }$ must be the same as the length of a sub-flow in $\mathcal { D } _ { U }$ . Otherwise, we can not use the same trained model from pre-training stage. Therefore, we prepare sub-flows of $\mathcal { D } _ { L }$ by following the same incremental sampling technique mentioned above. The only diference is, we include class labels for each of the sub-flows of $\mathcal { D } _ { L } , \mathcal { D } _ { L }$ is used in the fine-tuning stage as supervised dataset.

2) Pre-Training Stage: After preparing the unlabeled dataset $\mathcal { D } _ { U }$ , pre-training is performed to learn representation from $\mathcal { D } _ { U }$ . Fig. 4a shows every step of the pre-training stage. By following [12], we use two neural networks in the pretraining stage. One network is called the online network and the other is named as target network. The purpose of the target network is to provide the regression target for the online network.

Both of the neural networks in the pre-training stage have one encoder $f ,$ and one projector $g .$ The architecture of these two components is same but they are initialized with diferent sets of weights. Here, θ and $\xi$ represent the weights of online and target networks, respectively. The online network has one extra fully connected layer to predict the regression target provided by the target network. The dimension of the representation vector is very high. The purpose of the projectors $g _ { \theta }$ and $g _ { \xi }$ is to convert this high dimensional vector to a low dimension.

In this paper, we use ResNet [39] architecture as the encoder $( f _ { \theta }$ and $f _ { \xi } ) .$ . The goal in the pre-training stage of self-supervised learning is to separate diferent classes of data in the feature space by learning such representation of the data. ResNet is a popular choice of encoder in self-supervised learning due to it’s powerful representational ability by increasing the depth of the model. ResNet has some variations such as ResNet18, ResNet34, ResNet50 and so on [39]. ResNet34 is selected for our training because it provides a good trade-of between accuracy and training time compared to the other variations. All the 2D convolution layer and batch normalization layer of ResNet34 is replaced by 1D convolution layer and batch normalization layer respectively. For the projectors $( g _ { \theta }$ and g<sub>ξ</sub>), fully connected layers are used.

In the pre-training stage, two sub-flows with the same F id are randomly selected. Afterwards, one of the sub-flows is sent to the online network and the other to the target network as shown in Fig. 4a. Each network encodes its sub-flow, and the resulting representations are projected into a lowerdimensional space. The online network then uses its predictor to estimate the representation produced by the target network. Since both sub-flows originate from the same flow, this process encourages the encoder to learn similar representations for related sub-flows, while maintaining distinct representations for sub-flows from diferent flows. This makes the learned features more discriminative so that only a small amount of labeled data is needed for fine-tuning. During training, the online network is updated at each step, while the target network’s weights are maintained as an exponential moving average of the online network’s weights, controlled by a decay rate τ (Eq. 3).

$$
\xi \leftarrow \tau \xi + (1 - \tau) \theta\tag{3}
$$

During the pre-training stage, we use the same symmetric loss function from [12]. In this loss function, one mean squared loss $\mathcal { L } _ { \theta , \xi }$ is defined between the normalized predictions of the online network and the normalized projections of the target network. The mean squared loss is given in Eq. 4.

![](images/8ce2e1ff6e0f94e7feb0e3e0f620900eaadcde8b52ad725408a9c0aabafa3545.jpg)

(a) Pre-training stage of the proposed CSSL approach  
![](images/17c3c77343ec31acbb14fc53f9f2910cb7c174460f1d4954aaf83e51b94fa802.jpg)  
(b) Fine-tuning stage of the proposed CSSL approach  
Fig. 4. Overview of the proposed Contrastive Self-Supervised Learning (CSSL) approach.

$$
\mathcal {L} _ {\theta , \xi} \triangleq \left(\frac {q _ {\theta} (z _ {\theta})}{\| q _ {\theta} (z _ {\theta}) \| _ {2}} - \frac {z _ {\xi} ^ {\prime}}{\| z _ {\xi} ^ {\prime} \| _ {2}}\right) ^ {2}\tag{4}
$$

In Eq. 4, the loss is defined as the squared diference between $l _ { 2 }$ normalization of predictions of the online network $\left( q _ { \theta } ( z _ { \theta } ) \right)$ and projections of the target network $( z _ { \xi } ^ { \prime } )$ . Note that the loss in Eq. 4 is calculated by feeding $S _ { 1 }$ to the online network and $S _ { 2 }$ to the target network. To make the loss symmetric, another version of it is calculated by feeding $S _ { 1 }$ to the target network and $S _ { 2 }$ to the online network. This loss is denoted as $\widehat { \mathcal { L } _ { \theta , \xi } }$ . So, at each iteration a stochastic optimization step is performed to minimize the total loss $\mathcal { L } _ { \theta , \xi } ^ { T O T \bar { A } L } = \mathcal { L } _ { \theta , \xi } + \widehat { \mathcal { L } _ { \theta , \xi } }$ with respect to θ. Finally, we update θ according to the following equation.

$$
\theta \leftarrow o p t i m i z e r (\theta , \nabla_ {\theta} \mathcal {L} _ {\theta , \xi} ^ {T O T A L}, \eta)\tag{5}
$$

Here, η is the learning rate. In all our experiments, we use $\eta = 0 . 0 0 0 1$ with Adam [42] optimizer. A weight decay rate of $1 e ^ { - 6 }$ is used with the optimizer. In pre-training stage, we train the network for 50 epochs with a batch size 128. The target decay $\tau = 0 . 9 9$ is used. From the encoder, we obtain a representation vector of size 4096. In the projection layer, we reduce this representation vector to a 256 dimensional vector.

3) Fine-Tuning Stage: From the pre-training stage, we obtain the trained encoder for the online network $( f _ { \theta } )$ . In the fine-tuning stage, we freeze all the layers of the encoder. By freezing, we mean there is no update to the weights of the encoder layers in this stage. The frozen layers are represented by $f _ { \theta } ^ { \prime }$ in Fig. 4b. We use the small supervised dataset, $\mathcal { D } _ { L }$ in this stage. A new fully connected layer $q _ { \theta } ^ { \prime }$ is added as a prediction layer on top of the encoder. The number of neurons in this fully connected layer is equal to the number of class in our dataset $\mathcal { D } _ { L }$ . In this stage, we use the cross entropy loss (Eq. 6) to update the weights of the prediction layer $q _ { \theta } ^ { \prime }$

$$
\mathcal {L} (l, z _ {\theta} ^ {\prime}) \triangleq - \sum_ {\forall x} l (x) \log (z _ {\theta} ^ {\prime} (x))\tag{6}
$$

In Eq. 6, x represents one single observation from the distribution. l represents the true distribution and $z _ { \theta } ^ { \prime }$ represents the predicted distribution from the prediction layer.

In this stage, we train the network for 25 epochs with a batch size of 128. We use the Adam optimizer with a learning rate $1 e ^ { - 4 }$ and weight decay $1 e ^ { - 6 }$ . Our evaluation metrics and the results of our experiments are presented in the next section. In [43], [47], we demonstrate how the trained model can be utilized for real-life network trafic classification in a Software-Defined Networking (SDN) environment.

## A. Data Pre-Processing

The publicly available datasets are labeled data that can be used in a fully supervised setting. For the evaluation of our proposed self-supervised learning approaches, we create the unlabeled and labeled data by splitting the datasets. During the split, we make sure that the unlabeled dataset size is greater than the labeled one because our goal is to minimize the number of labeled data. In line with common self-supervised learning practice, our unlabeled dataset is substantially (∼ 2 3×) larger than the labeled dataset in our experiments. This follows prior work such as SimCLRv2 [46], where unlabeled data is 2 to 100 times larger than labeled subsets. For the unlabeled split of the dataset, we do not use the labels during training, although we have access to them. We use the QUIC and AppClassNet datasets in their original form [3], [27] and pre-process the Orange’20 and ISCX datasets as described in Section III-A.

1) Pre-Processing for the GSSL: In our proposed GSSL approach, we do not need to create two versions of the same input as we do in the contrastive approach. Therefore, there is no need to divide a flow into sub-flows. We split the dataset into unlabeled $\mathcal { G } _ { U }$ and labeled $\mathcal { G } _ { L }$ portions, as shown in Figure 5. Furthermore, we split the labeled dataset into training $( \mathcal { G } _ { L , t r a i n } )$ and testing $( \mathcal { G } _ { L , t e s t } ) . \mathcal { G } _ { L , t r a i n }$ is used for training in the fine-tuning stage, whereas $\mathcal { G } _ { L , t e s t }$ is used to evaluate the trained model.

We use a flow length of 1024 for all other datasets.

2) Pre-Processing for the CSSL: In the contrastive approach, we use the IAT and packet direction as features for all the datasets except AppClassNet. For AppClassNet, we use packet length and direction as features because these are the only features available in the dataset. The flow length is also fixed in this dataset which is 20. To create sub-flows for the AppClassNet dataset, we split each flow into two sub-flows of equal length. The first 10 packets belong to one sub-flow, and the rest of the packets belong to the other sub-flow. For the remaining datasets, sub-flows are created using incremental sampling with $\alpha = 2 2 , \beta = 1 0$ , and $\gamma = 1 . 6$ as described in Section III-C1.

## F. Discussion

All the experiments discussed above show the superiority of our proposed generative and contrastive approaches compared to the existing approach in [3], few-shot approaches [13], [15], and the corresponding supervised baselines. Among the compared few-shot approaches MatchingNet [15] outperforms ProtoNet [13] slightly. Overall, self-supervised approaches perform well compared to these two few-shot approaches in our experiments indicating the pre-training stage in the self-supervised approaches helps the model to learn a good representation of network flows in the feature space. The MatchingNet [15] uses an external memory to eliminate the fine-tuning stage of few-shot learning. However, the result does not show much improvement in our experiments. Evaluation results show that the proposed contrastive approach outperforms the self-supervised approach in [3] by more than 3%.

In terms of transferability, our contrastive approach shows superior performance against the existing self-supervised approach which indicates the pre-training stage in our proposed approach helps the model to learn good representation of the input data in the feature space. As a result, a few labeled data are suficient in the fine-tuning stage to achieve better accuracy. We could not compare our approaches with existing self-supervised approaches discussed in Section II-D due to the fundamental diference in the pre-training stage regarding the requirement of negative samples and the unavailability of the source code. When comparing generative and contrastive approaches, both have their advantages and disadvantages. The main advantage of the generative approach over the contrastive approach is lower computational complexity. Since we use transformer layers in the model architecture for a generative approach, the training is faster than that of a contrastive approach. This is due to the transformer layer’s capability to process sequential data in parallel. On the other hand, the contrastive approach needs to train two models simultaneously during the pre-training stage. As a result, training time of contrastive approach is higher than the generative counterpart. For example, the pre-training stage of the generative approach takes ∼35 minutes per epoch on the AppClassNet dataset with a batch size of 8192, whereas the contrastive approach takes ∼104 minutes per epoch with a batch size of 128.

In terms of performance, we observe that the proposed generative approach works better when features from flows with a larger number of packets are available. On the contrary, flows with a smaller number of packets are suficient for the contrastive learning approach to achieve a satisfactory accuracy. Since the contrastive approach divides a flow into sub-flows, one limitation of this approach is the inconsistency during real-time prediction. For example, the first sub-flow might be predicted to one class and the next sub-flow might be predicted to another class. One possible solution to this prediction inconsistency is to incorporate a voting mechanism during the real-time prediction in the contrastive approach. Since both the proposed generative and CSSL approaches outperform the corresponding supervised baselines by more than 3% with a small number of labeled data, one can select either the generative approach or the contrastive approach for encrypted network trafic classification based on either the length of the flow or the specification of the training environment.

## V. CONCLUSION

The task of identifying diferent types of network trafic has become more dificult due to the wide variety of applications and scarcity of correctly labeled data. However, collecting unlabeled network trafic is much easier compared to the tedious and error-prone task of trafic labeling. Additionally, as encrypted protocols continue to be deployed, relying on methods specific to particular protocols has become inefective. In this paper, we propose two self-supervised learning approaches, namely generative and contrastive learning, that rely on protocol-agnostic features from abundance of unlabeled data and a small amount of labeled data to classify encrypted network trafic. We evaluate the performance of our self-supervised approaches on four publicly available datasets representing diferent scenarios. The results of the extensive evaluation on four diferent datasets suggest that our proposed self-supervised approaches can achieve high accuracy, precision, recall, and F1 scores outperforming supervised, self-supervised baselines, and two state-of-the-art few-shot methods by more than 3%, 11%, and 17%, respectively. The proposed generative approach is computationally less expensive than the contrastive approach and hence allows faster training of the model. On the other hand, the proposed contrastive approach can achieve satisfactory accuracy with less number of packets in a network flow compared to the generative approach. Furthermore, the transferability analysis shows that the acquired knowledge during the pre-training stage of the contrastive approach is transferable to unseen datasets without losing much accuracy compared to an existing approach.

In our future research, the deployment process of the trained models in a real network will be investigated. We will address the problem of adding a new class to an already trained model according to our methods. It is often necessary to add a new class to a trained model without compromising the accuracy of existing classes. The explainability of the proposed methods needs to be explored as well. We will explore these capabilities of the proposed methods in our future work.
