# Enhancing Website Fingerprinting Attacks against Traffic Drift

## 0. 元信息

| 字段 | 内容 |
|---|---|
| **标题** | Enhancing Website Fingerprinting Attacks against Traffic Drift |
| **作者** | Xinhao Deng, Yixiang Zhang, Qi Li, Zhuotao Liu, Yabo Wang, Ke Xu |
| **机构** | 清华大学 INSC / DCST, 蚂蚁集团, 中关村实验室 |
| **会议** | NDSS 2026 |
| **数据集** | 350,000+ 真实 Tor 流量 trace（2024年3月–12月，2025年6月–7月），102个监控网站 + 20,000个非监控网站 |

## 1. 研究动机与问题定义

### 1.1 核心问题

深度学习驱动的网站指纹（WF）攻击在受控条件下效果显著，但在真实部署中面临**流量漂移（traffic drift）**问题——网站内容更新、Tor版本变化、用户浏览行为改变、网络条件波动等因素导致训练阶段与部署阶段的流量分布不一致，模型性能大幅下降。

### 1.2 现有方法的局限

| 方法类别 | 代表工作 | 局限性 |
|---|---|---|
| 周期性重训练 | DF, ARES, Tik-Tok | 需大规模标注数据，无法及时适应漂移 |
| 少样本微调 | TF, NetCLR, GANDALF | 仍依赖反映部署条件的标注流量 |
| 在线自适应 | OnlineWF | 从Tor出口节点收集标注流量，入口与出口流量模式差异大 |
| 数据增强+对比学习 | NetCLR | 仅对特定类型漂移有效，无法处理未知客户端侧因素 |

### 1.3 问题本质

现有WF攻击均**无法处理多源、动态演化的流量漂移**。在攻击阶段，攻击者只能获取无标签的漂移流量，而无法获取标注数据。因此需要一种**无需标签、仅利用无标注漂移流量进行在线自适应**的框架。

## 2. 方法：Proteus框架

### 2.1 核心思想

Proteus是一个**自适应WF攻击框架**，在攻击阶段持续利用无标签漂移流量微调现有DL-based WF模型，使其近实时适应流量漂移。核心洞见：**同一网站的原始流量与漂移流量之间存在内在关系**，可通过特征分布对齐来捕获这种关系。

### 2.2 三大模块

#### 模块一：特征分布对齐（Feature Distribution Alignment）

| 要素 | 说明 |
|---|---|
| **目标** | 最小化原始流量与漂移流量特征分布的差异 |
| **方法** | 高斯核函数映射至RKHS → 最小化MMD |
| **关键技术** | 动态带宽高斯核（自适应调整核带宽σ） |
| **损失函数** | L1 = (1/N²)ΣΣk(z_o^i, z_o^j) + (1/M²)ΣΣk(z_d^i, z_d^j) - (2/NM)ΣΣk(z_o^i, z_d^j) |
| **带宽公式** | σ = √((1/NM)ΣΣ\|\|z_o^i - z_d^j\|\|²) |
| **防止退化** | 同时最大化原始/漂移流量内部特征距离，保持类内变异 |

#### 模块二：模型置信度增强（Model Confidence Enhancement）

| 要素 | 说明 |
|---|---|
| **目标** | 提升模型对漂移流量的预测置信度 |
| **方法** | 优化预测的熵分布（Shannon entropy） |
| **关键技术** | batch内多样性约束机制 |
| **损失函数** | L2 = (1/B)ΣH(p_i) - H((1/B)Σp_j) |
| **设计要点** | 最小化每个样本的预测熵（提高置信度）+ 最大化batch内平均预测的熵（保证多样性，防止退化为单一类别） |

#### 模块三：自适应伪标签（Adaptive Pseudo-Labeling）

| 要素 | 说明 |
|---|---|
| **目标** | 生成可靠的伪标签用于有监督微调 |
| **方法** | 高斯混合模型（GMM）估计正确预测概率 |
| **GMM结构** | 两个高斯分量分别建模正确/错误预测的熵分布 |
| **参数更新** | EM算法 |
| **伪标签筛选** | 后验概率超过阈值的预测作为可靠伪标签 |
| **归一化** | 熵值归一化至[0,1]区间 |

### 2.3 整体流程

```
原始流量 + 漂移流量 → 特征分布对齐（MMD最小化）
    → 模型置信度增强（熵优化）
        → 自适应伪标签（GMM筛选）
            → 有监督微调 → 增强后的WF模型
```

### 2.4 与现有攻击的兼容性

Proteus可**无缝集成**现有DL-based WF攻击（如RF、ARES、DF等），仅需替换微调模型，不修改特征提取和模型架构。

## 3. 威胁模型

| 要素 | 说明 |
|---|---|
| **攻击者位置** | 客户端与Tor入口节点之间（ISP、AS、本地网络管理员） |
| **攻击能力** | 记录加密流量，不可解密 |
| **场景** | 闭合世界 + 开放世界 |
| **漂移类型** | 客户端侧（浏览行为/Tor版本）、服务器侧（网站内容更新）、网络侧（网络条件变化） |
| **防御考虑** | 客户端可部署WF防御（WTF-PAD, obfs4, Front） |

## 5. 核心实验结果

### 5.1 漂移量化分析（Energy Distance）

| 漂移场景 | 关键发现 |
|---|---|
| 时间漂移 | Day 270时top 20%网站的最小energy distance达5.68 |
| 浏览行为漂移 | 40%+网站的energy distance超过5.4 |
| Tor版本漂移 | 0.4.5→0.4.8距离8.8，版本差异越大漂移越严重 |
| 网络条件漂移 | 影响相对较小，SG↔UK距离约2.4 |

### 5.2 时间漂移性能（F1-score %）

| 攻击 | Day 14 | Day 30 | Day 90 | Day 150 | Day 270 |
|---|---|---|---|---|---|
| AWF | 48.84 | 45.36 | 37.49 | 32.21 | 28.64 |
| BAPM | 62.08 | 56.28 | 46.75 | 41.89 | 35.98 |
| ARES | 68.82 | 64.17 | 54.05 | 47.43 | 43.48 |
| DF | 71.94 | 65.79 | 55.24 | 48.91 | 44.48 |
| NetCLR | 72.71 | 66.92 | 55.81 | 49.03 | 43.92 |
| Tik-Tok | 77.89 | 72.36 | 60.87 | 52.56 | 46.58 |
| Var-CNN | 79.77 | 74.30 | 63.14 | 55.68 | 50.84 |
| RF | 87.63 | 81.62 | 72.02 | 66.25 | 59.57 |
| **Proteus** | **92.53** | **91.18** | **90.65** | **86.32** | **82.27** |

**关键发现**：Proteus在Day 270时F1达82.27%，而所有基线均低于60%。漂移时间越长，Proteus优势越明显。

### 5.3 网络条件漂移性能（F1-score %）

| 攻击 | SG | JP | USA | DE | UK |
|---|---|---|---|---|---|
| AWF w/o | 52.15 | 43.78 | 43.21 | 30.63 | 32.59 |
| AWF w/ Proteus | 54.25 | 46.87 | 44.96 | 31.59 | 35.87 |
| RF w/o | 88.87 | 87.45 | 83.10 | 20.85 | 17.38 |
| RF w/ Proteus | 90.63 | 90.98 | 92.64 | 81.66 | 84.60 |

**关键发现**：RF在DE/UK上性能暴跌（20.85%/17.38%），Proteus将其恢复至81.66%/84.60%（相对提升386.77%）。

### 5.4 浏览行为漂移性能（F1-score %）

| 攻击 | 首页 | 子页面 |
|---|---|---|
| RF | 89.00 | 44.76 |
| Proteus | 91.18 | 55.24 |

**关键发现**：子页面场景下基线F1平均下降57.32%，Proteus相对提升78.35%。

|---|---|---|---|---|

| **Proteus** | **82.27** | **88.28** | **81.66** | **55.24** |

### 5.6 开放世界时间漂移（F1-score %）

| 攻击 | Day 14 w/o → w/ | Day 270 w/o → w/ |
|---|---|---|
| AWF | 46.30 → 49.35 | 26.52 → 30.27 |
| ARES | 67.88 → 76.97 | 26.42 → 54.99 |

**关键发现**：开放世界中Proteus的增强效果更显著（Day 270 ARES提升108.14%）。

### 5.7 消融实验（270天漂移，F1-score %）

| 配置 | Precision | Recall | F1 |
|---|---|---|---|
| Base (RF) | 61.00 | 62.81 | 59.57 |
| + 特征分布对齐 | 65.16 | 68.12 | 65.51 |
| + 模型置信度增强 | 77.11 | 77.02 | 76.74 |
| + 自适应伪标签 | 76.86 | 79.97 | 76.01 |
| **Proteus（完整）** | **81.90** | **83.21** | **82.27** |

**关键发现**：三个模块均有贡献；模型置信度增强贡献最大（+28.82%）；三模块组合效果最优（+38.11%）。

### 5.8 与有监督微调对比（NetCLR，F1-score %）

| 方法 | Day 30 | Day 90 | Day 150 | Day 270 |
|---|---|---|---|---|
| Base | 66.92 | 55.81 | 49.03 | 43.92 |
| 有监督微调 | 67.87 | 62.33 | 54.96 | 56.79 |
| Proteus | 70.58 | 63.05 | 56.16 | 52.71 |
| 有监督+Proteus | 74.02 | 71.71 | 61.07 | 63.40 |

**关键发现**：短期漂移Proteus优于有监督微调；长期漂移有监督微调更优但不切实际（需标注）；两者结合效果最佳。

### 5.9 WF防御下的性能（F1-score，270天漂移）

| 攻击 | WTF-PAD w/o | WTF-PAD w/ Proteus | 提升 |
|---|---|---|---|
| RF | ~52 | ~81 | +56.29% |
| ARES | ~55 | ~77 | +39.90% |

obfs4下Proteus平均F1提升66.48%；Front防御下平均F1提升48.1%。

### 5.10 多标签浏览（F1-score %）

| 方法 | 20%重叠 | 80%重叠 |
|---|---|---|
| RF | 51.29 | 48.52 |
| RF + MMD | 58.21 | 54.67 |
| RF + Proteus | 81.11 | 73.62 |

### 5.11 延迟分析

集成Proteus后平均延迟增加约1.5ms（RTX 4090 GPU）。实际部署中可先识别网站，再用Proteus微调模型，不影响识别延迟。

## 6. 技术贡献与创新点

1. **首个自适应WF攻击框架**：无需标签，仅利用无标注漂移流量在攻击阶段持续微调
2. **三模块协同设计**：MMD特征对齐 + 熵优化置信度增强 + GMM伪标签，形成正反馈循环
3. **动态带宽高斯核**：自适应调整核带宽以应对不同类型漂移
4. **全面的漂移评估**：覆盖6种漂移场景，350,000+真实Tor trace，是迄今最全面的Tor流量漂移评估
5. **即插即用**：可与现有任意DL-based WF攻击集成

## 7. 局限性与未来方向

| 局限 | 说明 |
|---|---|
| 计算开销 | 需持续微调模型，增加计算成本 |
| 复杂漂移 | 对网站模板/内容大幅更新等复杂漂移尚未验证 |
| 数据规模依赖 | 无标注流量规模影响增强效果（40网站仅+3.71%，100网站+29.88%） |
| 对抗鲁棒性 | 未考虑对抗性机器学习攻击（adversarial ML可能破坏原始-漂移流量关系学习） |

**未来方向**：
- 对对抗性ML攻击的防御
- 更复杂漂移场景的验证
- 与有监督微调的更优结合策略

## 8. 对后续研究的启示

1. **流量漂移是WF攻击实际部署的核心瓶颈**：270天后所有基线F1降至60%以下，说明静态模型无法长期使用
2. **无监督自适应是可行路径**：Proteus证明无需标签即可有效适应漂移，为[[few-shot-traffic-learning]]提供了新范式
3. **特征分布对齐在WF领域有效**：MMD等域适应技术可直接应用于加密流量分析
4. **WF防御与WF攻击的军备竞赛新维度**：流量漂移既影响攻击也影响防御，需重新评估防御的实际效果
5. **对[[traffic-representation-learning]]的启示**：聚合特征（如RF使用）在漂移下更稳定，但需要自适应机制
