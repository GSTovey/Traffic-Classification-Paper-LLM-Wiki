## §1 一句话总结

提出MPAF（多阶段属性指纹）系统，利用TLS加密通信的三个阶段（域名查询、握手元数据、消息序列）分别提取属性，通过嵌入机制将离散属性转换为可计算向量，并设计基于叶节点掩码树的分类器实现分级分类，在4个数据集上实现96.33%-99.42%准确率和0.18s-0.45s平均等待时间，比现有方法AWT提升最高77.53倍。

## §2 摘要翻译

**原始摘要：**
The widespread use of cryptographic protocols such as Transport Layer Security (TLS) has necessitated the development of effective methods for encrypted traffic classification. The existing methods relying on a single feature source face challenges in achieving high accuracy and efficiency simultaneously. Additionally, there is a decrease in accuracy in complex scenarios, posing significant challenges for networks and security services based on application-level traffic classification. In this paper, we propose Multi-Phase Attribute Fingerprint (MPAF), an encrypted traffic classification system that overcomes these limitations. MPAF leverages three phases to separately leverage attributes that emerge at different time periods of encrypted traffic communication. Additionally, we transform discrete attributes into computable vectors through embedding and design a classifier for the multi-phase mechanism based on a leaf node masking tree. The experimental results show that MPAF achieves a classification accuracy ranging from 96.33% to 99.42% and an average waiting time (AWT) ranging from 0.18s to 0.45s. MPAF outperforms other approaches in scenarios with high robustness requirements, including small-scale training datasets, cross-dataset classification, and unknown application recognition.

**中文翻译：**
TLS等加密协议的广泛使用使得开发有效的加密流量分类方法成为必要。现有依赖单一特征源的方法在同时实现高准确率和高效率方面面临挑战。此外，在复杂场景中准确率下降，对基于应用层流量分类的网络和安全服务构成重大挑战。本文提出MPAF（多阶段属性指纹），一个克服这些限制的加密流量分类系统。MPAF利用三个阶段分别利用加密流量通信不同时间段出现的属性。此外，我们通过嵌入机制将离散属性转换为可计算向量，并设计了基于叶节点掩码树的多阶段分类器。实验结果表明，MPAF实现96.33%至99.42%的分类准确率和0.18s至0.45s的平均等待时间。MPAF在高鲁棒性需求场景中优于其他方法，包括小规模训练数据集、跨数据集分类和未知应用识别。

## §3 方法动机

**痛点问题：**
- 现有方法依赖单一特征源，难以同时实现高准确率和高效率
- 复杂场景下准确率下降（小样本、跨数据集、未知应用）
- 基于深度学习的方法需要大量数据包，导致平均等待时间长
- 属性重叠问题：同厂商应用共享域名和SNI属性（如支付宝/淘宝重叠34.84%）

**核心直觉：**
- TLS加密通信包含三个时间上分离的阶段：域名查询→握手→应用数据交换
- 超过一半的加密流可仅通过域名准确分类
- 大部分剩余流可通过握手元数据分类
- 少数残余流可通过消息序列分类
- 提前在前两阶段分类大部分流可显著提升整体效率

**方法动机：**
- 利用TLS通信的多阶段特性，逐级分流
- 域名阶段AWT=0（DNS记录在流开始前已生成）
- 握手阶段仅需前几个包即可完成分类
- 消息序列阶段作为兜底，处理前两阶段未分类的流

**核心假设：** TLS加密通信的三个阶段在时间上分离，各阶段的属性具有独立的分类能力，通过分级分类可以在保持高准确率的同时显著降低平均等待时间。

| **H2: 握手元数据假设** | 大部分剩余流可通过握手消息的原始字节分类 | 实验验证（Table VII） | 握手阶段分类19%-32%的流，准确率98.67%-99.86% |

## §4 方法设计

**整体流程：**

```
输入: TLS加密流量
  ↓
Step 0: 流量预处理
  - 将原始数据包重组为双向流
  - 解析TLS消息序列（握手+应用数据）
  - 提取DNS记录字典 D = {(DNd, Td) → Ad}
  ↓
Step 1: Phase 1 - 域名阶段
  - 域名提取器：通过IP地址和时间戳反向查找DNS记录
  - 域名向量化器：嵌入矩阵将域名转换为向量
  - 域名分类器：叶节点掩码树分类
  - 置信度足够 → 输出分类结果
  - 置信度不足 → 进入Phase 2
  ↓
Step 2: Phase 2 - 握手元数据阶段
  - 元数据提取器：提取前L个握手包的前B字节
  - Transformer编码器：12层自注意力网络提取特征
  - 元数据向量化器：嵌入机制向量化
  - 元数据分类器：叶节点掩码树分类
  - 置信度足够 → 输出分类结果
  - 置信度不足 → 进入Phase 3
  ↓
Step 3: Phase 3 - 消息序列阶段
  - 消息长度提取器：提取TLS消息长度序列
  - 序列分类器：直接使用长度向量，保留不纯叶节点
  ↓
输出: 应用分类结果
```

**关键公式：**

- 消息长度序列定义：$ML_f = [l_1^f, l_2^f, \dots, l_{h_{|H|}}^f]$
- 域名嵌入向量：$e_i^{DN} = [q_1^i, q_2^i, ..., q_N^i]$，其中 $q_j^i$ 表示第i个域名在第j个应用中出现的频率
- 分类置信度判断：若K棵树中超过 $K \times P$ 个给出相同标签，则确认分类

**优势：**
- 多阶段分级分类，大部分流在前两阶段快速处理
- 域名阶段AWT=0，显著降低整体等待时间
- 嵌入机制将离散域名转换为可计算向量
- 叶节点掩码树实现置信度控制，不纯节点传递到下一阶段

**局限：**
- 第三阶段（消息序列）准确率较低（34.67%-80.14%）
- 依赖DNS记录，DNS缓存机制可能影响域名提取
- 跨数据集性能下降明显（79.09% vs 99.42%）
- 属性重叠问题未完全解决

## 4.4 公式推导与理论基础

### 域名反向查找条件

对于加密流f（IP地址 $A_f$，首包时间戳 $T_f$），关联的DNS记录需满足三个条件：

1. **地址包含条件**：$A_f \in A_d$（DNS记录的权威地址包含流的IP）
2. **时间逻辑条件**：$T_d < T_f$（DNS查询时间早于流开始时间）
3. **最近时间条件**：多个记录满足前两个条件时，选择时间戳最接近的记录

### 域名嵌入矩阵

$$E_{DN} = [e_1^{DN}, e_2^{DN}, \dots, e_{|DN|}^{DN}]$$

其中每个向量 $e_i^{DN} = [q_1^i, q_2^i, ..., q_N^i]$ 对应第i个域名的嵌入，N为应用总数，$q_j^i$ 为该域名在第j个应用流量中的出现频率。

### Bi-gram编码

$$ToK_f = \{tok_1, \cdot\cdot\cdot, tok_i, \cdot\cdot\cdot, tok_{L*B/2}\}$$

每个token由两个相邻字节组成，取值范围0-65535。

### 叶节点掩码树分类机制

- C4.5决策树使用归一化信息增益作为分裂准则
- 训练样本达到预设阈值时停止分裂成为叶节点
- 前两阶段：掩码纯度值大于0的叶节点（多类别混合），未分类样本传递到下一阶段
- 最后阶段：保留不纯叶节点，确保所有流都能被分类

### Bootstrap机制

对训练集 $S = \{(x_j, y_j)\}_{j=1}^{|S|}$，随机森林通过有放回采样构建K个子集 $S' = \{Sub_1, \ldots, Sub_K\}$，在样本和特征两个层面进行采样以缓解过拟合。

## 4.5 Pipeline完整流程

```
Step 0: 流量预处理
  - 原始数据包 → 双向流重组
  - TLS协议解析 → 消息序列恢复
  - DNS包解析 → DNS记录字典构建
  ↓
Step 1: Phase 1 - 域名阶段
  - IP地址 + 时间戳 → DNS反向查找 → 域名
  - 域名 → 嵌入矩阵 → 向量
  - 向量 → 叶节点掩码树 → 分类/传递
  ↓
Step 2: Phase 2 - 握手元数据阶段
  - 前L个握手包 → 前B字节提取
  - 字节序列 → Bi-gram编码 → Token序列
  - Token序列 → Transformer编码器（12层自注意力）
  - 特征向量 → 嵌入机制 → 叶节点掩码树 → 分类/传递
  ↓
Step 3: Phase 3 - 消息序列阶段
  - TLS消息 → 长度序列提取
  - 长度序列 → 截断/零填充 → 固定长度向量
  - 向量 → 叶节点掩码树（保留不纯节点） → 分类
  ↓
输出: 应用分类结果
```

## 4.6 网络架构细节

### Transformer编码器（Phase 2）

| 组件 | 规格 | 说明 |
|------|------|------|
| 输入 | Token序列 $ToK_f$ | Bi-gram编码，每token 2字节 |
| 嵌入层 | d维高层抽象 | 可学习嵌入 |
| 位置编码 | 正弦嵌入 | 添加位置信息 |
| 自注意力编码器 | 12层堆叠 | h个并行自注意力层 + 前馈层 |
| 全连接层1 | 768维 | 特征提取 |
| 全连接层2 | N类 | 分类输出 |
| 激活函数 | tanh | 特征张量处理 |

### 分类器参数选择

| 参数 | 搜索范围 | 最优值 | 说明 |
|------|----------|--------|------|
| K（树数量） | {10, 20, 30} | 30 | 随机森林中决策树数量 |
| P（置信度阈值） | {0.6, 0.7, 0.8, 0.9, 1.0} | 0.6 | 分类确认阈值 |
| L（握手包数） | - | ≤5 | Phase 2使用的消息数 |
| B（字节数） | - | - | 每包提取的字节数 |
| \|H\|（消息数） | - | ≤12 | Phase 3使用的消息数 |

## §5 与其他方法对比

**创新点：**
1. 首次系统利用TLS通信三阶段特性进行加密流量分类
2. 提出叶节点掩码树分类器，实现置信度控制的分级分类
3. 嵌入机制将离散域名属性转换为可计算向量
4. 多阶段设计显著降低平均等待时间

**与基线对比：**
- 对比方法: FS-Net, EBSNN, ET-BERT, ETC-PS, Input-Agnostic, AMUS
- 改进点:
  - 准确率: 96.33%-99.42%（与ET-BERT相当）
  - AWT: 0.18s-0.45s（比现有方法提升最高77.53倍）
  - 小样本鲁棒性: 20%训练数据即可保持高准确率
  - 跨数据集: 79.09%准确率（优于其他方法的17.24%-47.75%）
  - 未知应用识别: 93.50%-97.09%准确率，100%召回率

## 5.1 方法创新点

1. **多阶段分级分类机制**：利用TLS通信三阶段的时间分离特性，逐级分流，大部分流在前两阶段快速处理
2. **叶节点掩码树分类器**：基于C4.5决策树，掩码不纯叶节点实现置信度控制，不纯样本传递到下一阶段
3. **域名嵌入机制**：将离散域名转换为基于出现频率的向量表示，支持向量计算
4. **Transformer编码器**：利用预训练模型的特征提取能力，从握手消息原始字节中提取分类特征
5. **Bootstrap机制**：通过随机森林的样本和特征采样缓解过拟合

## §7 学习与应用

**开源情况：**
- 论文未明确说明是否开源代码
- 使用公开数据集：Van Ede et al. 2020 Cross-Platform数据集

**复现要点：**
- 需要实现DNS记录字典构建和反向查找
- 需要实现域名嵌入矩阵
- 需要实现Transformer编码器（可基于ET-BERT）
- 需要实现叶节点掩码树分类器
- 需要实现随机森林的Bootstrap机制

## 7.2 技术要点

1. **DNS反向查找**：通过IP地址和时间戳匹配DNS记录，处理一对多关系和DNS缓存
2. **域名嵌入**：基于出现频率的向量表示，将离散域名转换为可计算向量
3. **Bi-gram编码**：将字节序列转换为token序列，每个token由两个相邻字节组成
4. **Transformer编码器**：12层自注意力网络，768维特征提取
5. **叶节点掩码树**：C4.5决策树的改进，掩码不纯叶节点实现置信度控制
6. **随机森林Bootstrap**：样本和特征两个层面的采样，缓解过拟合

## 7.3 局限性

1. **第三阶段准确率低**：消息序列阶段准确率仅34.67%-80.14%，对残余流分类能力有限
2. **跨数据集性能下降明显**：从99.42%降至79.09%，下降20.33%
3. **属性重叠问题**：同厂商应用共享域名和SNI属性（如支付宝/淘宝重叠34.84%），影响分类
4. **DNS依赖**：依赖DNS记录进行域名提取，DNS缓存机制可能影响效果
5. **iOS数据集表现较弱**：96.33%准确率，低于Android的99.09%，主要受域名阶段影响
6. **未知应用识别阈值敏感**：概率阈值τ的选择影响未知应用识别性能

## 7.5 可复现性要点

- **代码**：论文未明确说明是否开源
- **数据集**：
  - 自收集数据集：15个应用，手动/自动两种收集方式
  - 公开数据集：Van Ede et al. 2020 Cross-Platform (Android/iOS)
- **关键实现细节**：
  - DNS记录字典：{(域名, 时间戳) → 权威地址}
  - 域名嵌入矩阵：N维向量，N为应用数
  - Transformer编码器：12层，768维，基于ET-BERT参数
  - 叶节点掩码树：C4.5 + 纯度阈值掩码
  - 随机森林：K=30棵树，P=0.6置信度阈值
- **硬件要求**：2*Intel Xeon Gold 6330 CPU, 256GB DDR4内存
- **关键依赖**：PyTorch（用于Transformer和深度学习组件）

**迁移价值：**
- 多阶段分类思想可应用于其他需要实时性的流量分析任务
- DNS反向查找方法可用于其他基于域名的流量分析
- 叶节点掩码树分类器可应用于其他需要置信度控制的分类任务
- 嵌入机制可处理其他离散网络属性

## §8 总结

**核心思想：** 利用TLS加密通信的三阶段时间分离特性，通过多阶段分级分类实现高准确率和低等待时间的加密流量分类。

**快速流程：**
```
TLS加密流量 → DNS反向查找 → 域名嵌入 → 域名分类（AWT=0）
    ↓ (未分类流)
握手包提取 → Bi-gram编码 → Transformer编码 → 元数据分类
    ↓ (未分类流)
消息长度提取 → 长度向量 → 序列分类（兜底）
    ↓
应用分类结果（Acc 96.33%-99.42%, AWT 0.18s-0.45s）
```

## 13.3 方法呈现技巧

**技巧1：分阶段递进设计**
- 每个阶段有明确的目标、输入、输出
- 阶段之间通过置信度阈值连接
- 不纯叶节点传递机制实现自然分流

**技巧2：嵌入机制处理离散属性**
- 将离散域名转换为基于出现频率的向量
- 支持向量计算，为分类器提供连续输入
- 未见过的域名映射为零向量

**技巧3：叶节点掩码树的巧妙设计**
- 基于C4.5决策树，但掩码不纯叶节点
- 前两阶段追求高准确率，不纯节点传递
- 最后阶段保留不纯节点，确保全覆盖
